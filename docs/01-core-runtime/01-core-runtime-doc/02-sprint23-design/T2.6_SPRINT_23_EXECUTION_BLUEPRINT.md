## OBJETIVO PRINCIPAL

Integrar el dominio de **Formularios Dinámicos** al Runtime Engine mediante:

* **FORM_CREATED**
* **FORM_VERIFIED**

sin intervenir:

* Dispatches
* Recovery
* Selection
* Decision avanzada
* Provider Binding

El objetivo del Sprint 23 es habilitar:

* FORM_CREATED → Runtime Audit Layer → Runtime Analytics Layer
* FORM_VERIFIED → Runtime Audit Layer → Runtime Analytics Layer

con señales mínimas para Scoring.

## FASE 2 — DEPENDENCY GRAPH (orden obligatorio)

## BLOQUE 1 — Identity Strategy
**Objetivo:** validar identidad estable para integración.

**Elementos:**
* actorId
* eventId
* correlationId

**Resultado esperado:**
* actorId → profiles.id
* eventId → sgc_audit_logs.id
* correlationId → sgc_form_responses.id

**Estado esperado:** READY

## BLOQUE 2 — Runtime Event Taxonomy
**Objetivo:** eliminar dependencia conceptual de create/verify → usar taxonomía runtime.

**Resultado esperado:**
* FORM_CREATED
* FORM_VERIFIED

**Estado esperado:** READY

## BLOQUE 3 — Payload Contract
**Objetivo:** definir información mínima para ingresar al Runtime.

**Restricción:**
* NO consumir EAV raw
* NO usar directamente sgc_response_values como payload runtime

**Resultado esperado:**
* payload conceptual normalizado

**Estado esperado:** PARTIAL → READY

## BLOQUE 4 — Audit Ingestion
**Objetivo:** permitir que FORM_CREATED y FORM_VERIFIED ingresen al Audit Layer.

**Estado esperado:** READY

## BLOQUE 5 — Analytics Consumption
**Objetivo:** consumir eventos auditados para analytics básicos.

**Estado esperado:** READY

## BLOQUE 6 — Scoring Signals (limitado)
**Objetivo:** derivar señales mínimas.

**Ejemplos:**
* completado
* verificado
* tiempo entre create y verify
* evidencia presente

**Estado esperado:** PARTIAL
