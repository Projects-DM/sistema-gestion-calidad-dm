## FASE 8 — EXECUTIVE DECISION REPORT

### 1. Qué NO debe tocarse
- Selection
- Recovery
- Provider Binding
- Dispatches integration
- EAV raw como payload runtime

### 2. Qué debe adaptarse
- Taxonomía runtime de eventType (create/verify → FORM_CREATED/FORM_VERIFIED)
- Normalización conceptual de payload (no EAV raw)

### 3. Qué debe integrarse primero
- Formularios dinámicos: FORM_CREATED/FORM_VERIFIED → Audit → Analytics

### 4. Qué debe posponerse
- Decision/Selection/Recovery
- Dispatches (audit inexistente)
- Certificados/Technical Sheets (fuera de evidencia consolidada)

### 5. Qué bloquea Sprint 23
- Payload normalizado determinista (payload PARTIAL en T2.4)
- Replay markers completos (recovery NOT_READY)

### 6. Qué desbloquea Sprint 24
- Mayor consistencia de analytics/scoring (reducir PARTIAL a READY en señales derivables)

### 7. Cuál es la ruta crítica
- eventType taxonomy + payload contract mínimo + Audit ingestion determinista
- luego Analytics snapshots para scoring básico

### 8. Veredicto final (una sola opción)
**PARTIAL**

Justificación consolidada:
- T2.3: Audit/Analytics READY para formularios, Scoring PARTIAL y Decision/Selection/Recovery NOT_READY.
- T2.4: contrato mínimo con payload normalizado “PARTIAL” y replay seguro completo “PARTIAL/INSUFICIENTE” para Recovery; Sprint 23 aprobado con alcance limitado.
